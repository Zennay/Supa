## Risk and implementation
Before this change, the M5 private snapshot verified HTML file descriptors with O_NOFOLLOW but constructed their names from the original supermarket path after earlier lstat/realpath validation. Replacing that **parent folder** with a symlink between validation and HTML open could redirect the reader even though the final .html component was never a symlink. A matching SHA would prove content but not its nominated tree origin.
New `scripts/m5-pin-capture-store.mjs` pins original capture root AND supermarket directory by Linux O_RDONLY|O_DIRECTORY|O_NOFOLLOW descriptors, verifies original lstat dev/ino against opened fstat, and opens each child HTML through `/proc/self/fd/<store-fd>/<id>.html`. This child path follows the already-opened store directory inode, not the mutable original parent name. `readVerifiedHtml` retains O_NOFOLLOW on the final file plus exact input SHA, 8MiB/64KiB resource ceiling, strict UTF-8 and snapshot cleanup. Handles close with finally on successful output and error. The code deliberately fails closed on a platform without Linux proc-fd child lookup: no unsafe silent fallback.

## Product-only synthetic acceptance

Reject initial symlinked root and store; reject invalid traversal, Unicode, blank or overlong IDs; propagate injected callback errors; preserve P1 without HTML, P2 baseline missing and legitimate independent older P3; CLI remains private with no root or proc-fd path leakage.
