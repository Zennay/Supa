## New behavior
- `--output` must occur at most once and have a nonempty, non-flag filename. Missing, duplicate, flag-valued and unknown options are rejected **before** reading/revealing the private report. Deliberate CLI execution without `--output` retains the existing stdout behavior; external callers must explicitly choose output-file mode for private data.
- The derived JSON is fully written to a randomly named, exclusive-create (mode **0600**) temporary file in the chosen destination directory, flushed and closed; a same-filesystem `link(temp, output)` publishes a complete inode **only when the destination does not exist**. The temporary name is unlinked in finally, regardless of whether publication succeeded. This avoids truncating the source, symlink aliases, hardlinks, existing report files and permissive 0644 destinations, and avoids partially visible destination data before writing completes.
- Retrying the identical output name intentionally fails with `EEXIST`; researchers must explicitly choose a fresh report target instead of overwriting or mutating history. If an existing destination has overly broad permissions, it is **not modified**, not silently chmodded.
- This is a strict no-overwrite publication policy, not an authorization gate. It is not proof of resistance to every malicious concurrent filesystem namespace mutation or disk-level durability event. The directory and output path still require trusted ownership/permissions; do not treat this as a sandbox.
